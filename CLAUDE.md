# Sivree — working notes for Claude

The app was named Sivry until 2026-10-20 (旧名 Sivry). Persisted identifiers keep the old `sivry` prefix on purpose (localStorage keys, the Drive file `sivry-settings.json`); `npm run check:brand` flags any other leftover.

Personal news app that shows only **primary sources** (governments, companies, research bodies, NPOs). Read `PHILOSOPHY.md` (founding purpose and long-term hypotheses), `PRODUCT.md` (principles) and `BACKLOG.md` (decisions, market view) before proposing features. Keep long-term AI/SI hypotheses distinct from current capabilities and approved scope.
Live: https://sivree.com/ (GitHub Pages with the custom domain since 2026-10-23; www redirects to it, and the old https://ty-knowgic.github.io/sivree-app/ redirects too. "Publish Sivree" workflow runs on push and every ~3 h). DNS is at Porkbun: leave the Workspace mail records (MX, SPF, google-site-verification, google._domainkey, _dmarc) alone.

## Layout
- `src/` Express + TypeScript server and shared logic (profile matching, pipeline, robots, vectors). `src/browser/main.ts` is the in-browser API used by the static site (bundled to `static-api.js`).
- `public/` static UI (`app.js`, `i18n.js`, `sync.js`, `legal.html`, `locales/*.json`). `site/` is the gitignored build output.
- `scripts/` checks and tests. `.github/workflows/publish.yml` runs them in CI.

## Conventions that bite
- **i18n**: the Japanese text is the key. Every new UI string needs an entry in all 12 other `public/locales/*.json` (`check:locales` fails otherwise). New source names **and labels** go in `locales/sources.json`; `check:i18n-keys` fails if code uses a Japanese string that isn't in the dictionaries, `check:source-names` fails for untranslated feed names/labels. Anything generated into data (hashtags, labels) must be translated at render time.
- **Python edits**: use files, not stdin heredocs with non-ASCII (macOS python 3.9 mangles long lines): write the script to the scratchpad and run it with `exec(compile(open(f, encoding='utf-8').read(), f, 'exec'))`. No `sed -i` (macOS BSD sed).
- jsdom tests: `const`/`let` in `app.js` are invisible to `window.eval`; expose what a test needs via `window.__t` (append `window.__t = {...}` / `window.__ready = i18nReady` to the evaluated source; `await window.i18nReady` is a no-op).
- Static build is cached 10 min by GitHub Pages: asset URLs carry `?v=<sha>`.
- **Feeds** live in `src/feeds/` (`officialFeeds` is re-exported from `src/newsPipeline.ts`). An official feed needs `level` (`international`/`national`/`regional`/`local`); regional/local also need `area` (ISO 3166-2), local needs `city`. The feeds that existed on 2026-10-20 (99 entries, 94 distinct URLs; Cision Canada removed 2026-10-21 when its feed disappeared, so 93) are frozen in `scripts/frozen-default-feeds.json` (feed URL → id): don't change their `feedUrl` (it changes the id and drops users' on/off choices), and any feed added later must carry `since: 'YYYY-MM-DD'` (it then stays off by default). A feed in a `pack` must have `terms: 'A'`; `terms: 'B1'` requires `titleOnly`. `test:feeds` and `test:tiers` enforce this. Professional sources (2026-10-23, 53 feeds incl. 11 read from list pages, all candidates) are in `src/feeds/professional.ts`; the two packs (`legal`, `finance`; name and blurb are UI strings in every locale) are in `src/feeds/packs.ts` and appear grouped inside Settings → 候補 labelled 「正式版では有償（ベータ中は無料）」. `test:feeds` pins each pack's sources and the international/regional level lists — changing them needs the user's OK. The State Department feed has returned 403 since 2026-10-29; its free candidate replacements (White House Presidential Actions / Fact Sheets, Federal Register State Department sanctions) are in `src/feeds/usPolicy.ts`, and `test-tiers` pins each feed file's count. A page without RSS can be read with `htmlList` (CSS selectors for rows/link/date, `src/htmlList.ts`): headline, date and link only, shown like `titleOnly`, no article-page fetches; add one only after reading that site's terms. Categories come only from words in headline + description (`CATEGORY_RULES` in `src/newsPipeline.ts`); for 生成AI, non-corporate sources also count any AI/人工知能 mention, corporate ones only named model companies (2026-10-29). Wire feeds with `datelineRegion` (PR Newswire) take each article's region from its dateline (`src/dateline.ts`); unknown or US datelines keep the feed's region. Articles are capped per group in `trimArchive` (3000 for default sources, 1000 for candidates) so candidates never push default articles out.
- **Candidates**: a feed that is not `defaultOn` (`src/sourceTier.ts`) is a candidate: hidden unless its id is in `profile.extraSources` (`candidate: true` in `listSources()`). Turning a candidate off removes it from `extraSources` **and** adds it to `excludedSources`, so a migration redone after an old cached page saved the profile can't bring it back. `migrateProfile` (`src/profile.ts`, run by every `loadProfile`/`saveProfile`, so paste and Drive sync are covered) moves the old always-on Waterloo/Ontario sources into `extraSources`; their ids are fixed in `LEGACY_DEFAULT_CANDIDATES`. `test:migrate` checks that nobody's visible articles change.
- CSP is a meta tag in `public/index.html`: any new external host must be added deliberately and justified in the privacy page.

## Loading and refresh (2026-10-24; data layout 2026-10-30)
- Current clients read schema 3 files written by `scripts/export-data.ts` via `src/staticData.ts`: `list.json` (one self-consistent file with items, list summary text, sources and compact analysis — everything a list or briefing needs), `details.json` (summary key points/basis, fetched after the first list is visible) and `head.json` (generation only, for update checks). `meta/news/sources/summaries/analysis/vectors.json` stay published for already-open older clients and the coverage audit.
- Compact analysis drops topic similarities below `threshold − WEAK_MARGIN`: every rule in `matchTopics` treats them alike, so results are identical (`test:performance` checks this). Change the margins in `profile.ts` only together with `scoreFloor`.
- Static clients restore the last complete snapshot (`list`/`details` response text in IndexedDB key `v3`) and apply current local profile filters. If storage hasn't answered within 800 ms, the network starts too and whichever completes first is shown; the other never replaces cards (a newer one becomes the pending update).
- Each browsing session pins one data generation across all tabs, details and pagination. Background work (details, snapshot write, update check) waits for `sivree:list-ready` from `app.js`. Update checks download and persist a pending generation and show a fixed update button; they never replace cards. Only tapping that button or the logo adopts pending data. Resume after 10 minutes checks for updates only.
- Scripts are `defer` in `<head>` (parallel download); `static-api.js` runs first so `list.json` is requested early. `profile.ts` imports zod as a namespace so the bundle leaves out zod's locales (489 KB → 126 KB).
- `test:performance` verifies analysis equivalence, snapshot restore offline, details generation checks, the storage/network race, current hidden-item filters and explicit generation adoption. It requires no listening server. `sivree:start` and `sivree:list-ready` performance marks support device profiling; the preview server gzips like GitHub Pages so throttled timings are realistic.

## Decisions already made (don't reopen without being asked)
- Operator (2026-10-23): **Knowgic Technology** (sole proprietorship, Waterloo, Ontario, Canada; https://knowgictech.com/). Shown on `public/about.html`, the operator line of `legal.html`, the settings footer, `LICENSE` and README. If it incorporates (considered for 2027), update all of these together.
- User settings live **only on the client**. No server-side user data, no accounts, **no email digest**. Cross-device = copy/paste, or optional Google Drive appDataFolder sync (needs `CLIENT_ID` in `public/sync.js`).
- Audience and pricing (2026-10-20): professionals whose work depends on primary sources (consultants, licensed professionals, think-tank researchers). Personal non-business use, educational institutions and charities free; business/organizational use (companies, firms, public research organizations) paid annually per organization, free during beta. Entitlement = signed license key checked on the device, **not** accounts. Details in `PRODUCT.md` / `BACKLOG.md`. Code license: PolyForm Noncommercial 1.0.0 (`LICENSE`). Embedding model pinned to `embeddinggemma:300m` (Gemma terms read; only outputs ship). Per-source terms: `SOURCE_TERMS.md`; the B1 sources (commercial use restricted; 15 on 2026-10-20, 9 more professional ones on 2026-10-23) show **headline + link only** (`titleOnly` on the feed; no description, summary or image); ask permission later based on usage/feedback; press-release wires still to be asked. Trademark: preliminary search clean, nothing filed.
- Saved articles and citations (2026-10-20): a saved article is a **snapshot in the profile** (`savedItems`: original headline, source name, URL, dates, user note; no description/summary/image, so it is safe for `titleOnly` sources and survives the 30-day archive). Settings reset keeps it; settings paste **merges** it (`SivreeSaved.mergeSavedItems`), never overwrites. Citations use the source's original headline and the **publisher region's** calendar date (`REGION_TIMEZONE` in `public/saved.js`); the user's notes appear only in CSV and RIS. All profile writes in `app.js` go through the serialized `updateProfile`.
- Article feedback "関心がない…" (2026-10-27): a button on every list card (outside the `<a>`) and in the detail actions opens a sheet with four choices: lower the matched topic's priority one step (`WEIGHT_STEPS`), add an excluded keyword to a matched topic (`topic.excludeKeywords`, optional; a topic skips articles containing it, also for source/semantic matches), turn the source off, hide this article (`hiddenItems`). The first two are logged in `profile.adjustments` (newest first, 60 max) and listed in Settings → 関心トピック → 「関心の調整」 with undo (applied to the draft, committed by 保存). Whether an entry is still in effect is derived from the topic's current value (`SivreeInterest.stateOf`), never from the log alone. Logic is in `public/interest.js` (no Japanese strings); sync merges `excludeKeywords` per element and `adjustments` per id (`mergeProfiles`). An old cached page that saves the profile drops both fields (exclusions stop applying; nothing else breaks; `test:migrate` section 5). No learning, no implicit signals.
- Logo (2026-10-20; logotype 2026-10-29): the bracket-and-dot mark plus **SIVREE** outlined from Inter 700, upright, tight tracking with per-pair values (`BRAND.md`, `brand/build-wordmark.mjs`). The header shows the outlined SVG and keeps a visually hidden "Sivree" in the DOM; every sentence/UI string keeps "Sivree". Brand colour #5b5bd6 (provisional). Details, asset list and how to regenerate the PNGs: `BRAND.md`.
- Drive sync (2026-10-21, `public/sync.js`): Google's token model gives a token only through a popup opened **synchronously inside a tap** (iPhone blocks it after any `await`), and offers no silent renewal. So GIS is preloaded when sync is on, the token (~1 h) is kept in localStorage. When it expires, a header sync button and a load toast appear, and Save/paste in settings call `SivreeSync.prepare()` so the popup opens in that tap; no popup without a tap. When both devices changed, there is no dialog: a 3-way merge against the last-synced copy (`sivree:sync-base`) runs per field. List fields merge per element, so deletions propagate. A device without a base takes Drive's settings and keeps both devices' saved and hidden items. `test:sync` models the iPhone popup rule.
