# 外部からの声の記録

試用（[beta-pilot.md](beta-pilot.md)）の外で、運営者が受けた感想の置き場。需要の証拠としては数えない（12/4 の判定は試用の記録だけで行う）。公開リポジトリなので、個人名・所属先の特定につながる情報は書かない。声の出所は、本人の許可なく紹介ページ・デモ・募集文面で引用しない。

## 2026-11-05 日本の在外公館の担当官（経済担当）

- **経緯**: 別件（日加友好100周年に向けた事業の相談）の Teams 会議で、Sivree を短く紹介した。会議の録音は音声認識が崩れていて内容を読めないため、以下は Tetsu が覚えていることの伝聞（2026-11-07 に聞き取り）。画面を触っての評価ではなく、概念への反応。
- **言われたこと**
  1. 各省庁の若手は毎朝、各省の発表や民間の発表資料を細かく横断して見ていて、閣僚や上長に出すブリーフィング資料の作成にかなりの労力をかけている。
  2. 「一次情報源だけから情報を抜き出す」という Sivree のコンセプトに、かなり共感されたようだった。
- **扱い**: 1人・非公式・伝聞。「共感」は「使う」「払う」ではない。2026-10-30 の決定（政府職員は試用の候補にしない。相手から聞かれたときだけ紹介する。政府機関の料金と倫理面は未決）はそのまま。この声をきっかけに営業はしない。

### この声が示す仕事の形

「毎朝・官民の発表を横断して見る」→「上の人に出す資料にする」。Sivree が既に持つのは前半（横断・出所の表示）と、保存と引用。持っていないのは、資料にする最後の一段と、漏れなく見るための網羅。

| その人の作業 | Sivree にあるもの | 足りないもの |
|---|---|---|
| 毎朝、各省と民間の発表を横断して見る | 地域・分野の絞り込み、前回以降の「新着」印、今日のブリーフィング（最大5件・話題が偏らない） | 昨夕から今朝までを漏れなく見る一覧（ブリーフィングは5件で終わる設計で、網羅の道具ではない）。日本の府省庁の網羅（下表） |
| 上長向けの資料に載せる | 保存と引用（出典表記・Markdown・BibTeX・RIS・CSV）。メモは CSV と RIS にだけ入る | 資料に貼れる形（日付・発信元・見出し・URL・自分のメモを1件ずつ並べた文）で、保存した発表をまとめて書き出す |
| 民間の発表も見る | PR TIMES・@Press（既定オン）。CONTENT-01 で企業配信の既定の扱いが利用者の判断待ち | この声は、企業の発表を既定から外す方向には働かない（1人分の参考） |

### 盛り込む案（11/2 の決定により、どれも Tetsu の判断があるまで着手しない）

優先度は、この用途に効く順。

1. **UX-02 の継続（P1・既存）**: 「毎朝開く」が前提の用途なので、開く手間・開いた直後のもたつきの解消は引き続き最優先。新しい作業は無い。
2. **BRIEF-01（P2）**: 保存した発表を、資料に貼れる形でまとめて書き出す。既存の引用書き出し（`formatCitations`）の延長で小さい。AI の文は足さず、載せるのは保存の写しが持つ見出し・発信元・日付・URL・自分のメモまで（説明文は持たない設計なので、利用条件が見出しのみの情報源でも安全）。
3. **DATA-04（P2）**: 府省庁の網羅。取れるところ（農水省・警察庁から）を、robots.txt と利用条件を読んでから `since` つきの候補で足す。取れない省庁は、名前を出して「取得できない」と見せる案も検討（利用者が、無いのではなく取れないのだと分かる）。
4. **SCAN-01（案・要設計）**: 期間（昨夕〜今朝）と発信元（府省）で漏れなく見る一覧。ブリーフィングを5件に限る原則（PRODUCT.md 原則2）は崩さず、別の画面にする。既存の「新着」印・ホームの並びとの重なりを先に確かめる。
5. **試用の質問に足す案**（文書だけ・凍結の対象外）: 14日目に「上長や顧客に出す資料づくりに使ったか」「毎朝の確認の手間は減ったか」。`beta-pilot.md` の変更なので Tetsu の了承後に入れる。

### Tetsu の判断が要ること

- 想定する利用者（PRODUCT.md）に「官公庁の政策担当」を加えるか。加える前に、政府機関の料金・倫理面（BACKLOG「有料プランの対象の線引き」・`beta-pilot.md`）の整理が先。この記録では何も変えていない。
- 上の案のうち、11/2 の凍結の例外にするものがあるか。
