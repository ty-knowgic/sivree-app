# 見出しの翻訳（設定）: 方式の比較と推奨

作成: 2026-10-30。PRODUCT.md の未決定「翻訳を AI が行う場合の表示と許容範囲」への提案。**未実装**（下の「決めてほしいこと」の回答待ち）。

## 求められていること
設定のチェックボックスで「見出しを原文のまま」か「表示言語（13言語: ja・en・de・es・fil・fr・id・ms・pt・th・vi・zh-Hans・zh-Hant）に自動翻訳」を選ぶ。訳は原文の意味と文脈にできるだけ忠実に。原文の見出しはいつでも見られる。

## 守る条件
- 一次情報への忠実さ: 訳は「機械翻訳」と分かる表示にする（PRODUCT.md 24行目）。詳細画面には原文の見出しを常に出す（いまの `showOriginal` と同じ形）。
- 引用・保存は原文のまま: `saved.js` は `item.title`（原題）を保存しており、訳を渡さない。トピックの一致・並び順・検索も原文で判定する（訳で表示が変わっても、どの記事が出るかは変わらない）。
- 特定の生成AIに依存しない: エンジンは差し替え可能・商用利用できるオープンなモデルに限る。
- 設定は端末内だけ: 「翻訳する」は画像の表示と同じく端末の設定（localStorage）。サーバーに利用者の言語を送らない。
- CSP: 新しい外部ホストを足さない（訳は自分のサイトの静的ファイルとして配る）。
- 読み込み時間: 訳は最初のカードの必須データ（`list.json`）に入れず、オンにした人だけが自分の言語のファイル1つを後から読む。

## 方式の比較

| 方式 | 忠実さ・文脈 | iPhone での動作 | 費用・運用 | 利用条件（B1） | 判定 |
|---|---|---|---|---|---|
| A. 公開の処理で事前に翻訳し、言語ごとの静的ファイルで配る | 発信元名・説明文を文脈として渡せる。全員に同じ訳を見せられる（誤訳の確認・修正が1か所） | 追加ファイル1つ（新着分だけなら数十〜数百KB）。端末の計算なし | GitHub Actions の CPU で毎回の新着（約45件/3時間）×12言語。訳は `data/` の蓄積に保存して一度だけ | 訳を**公開データとして再配布**することになる。B1 では許諾が要ると読むのが安全 | **推奨**（A の情報源から） |
| B. 端末の中で翻訳（ブラウザ内のモデル） | 文単位の訳。文脈は渡しにくい | Safari には Chrome の Translator API がない。WASM のモデルは1言語対あたり数十〜数百MB・遅い・電池を使う。2秒目標と両立しない | 配信は静的ファイル、端末の負荷が大きい | 再配布ではない（利用者のブラウザの翻訳機能に近い） | 不採用（iPhone で実用にならない） |
| C. 外部の翻訳 API（DeepL・Google など） | 高い | 速い | 有料・鍵を置くサーバーが要る（サーバーを持たない設計に反する）。見出しと利用者の言語が外部に出る。CSP に外部ホスト追加 | 外部サービスへの送信も再利用にあたりうる | 不採用 |
| D. 何もしない（Safari の「ページを翻訳」を案内） | ページ全体を訳す。原文との対応が見えない | 動く | ゼロ | 再配布ではない | 当面の代替として案内は可 |

### A のエンジン候補（商用利用できるもの。性能はまだ測っていない）
- **MADLAD-400 3B（Apache-2.0、400言語以上）**: 翻訳専用。CTranslate2 の int8 版で CPU でも動く。13言語をすべて含む。文脈は渡せない（見出しだけを訳す）。
- **TranslateGemma 4B（Gemma 利用規約、55言語）**: 2026年1月公開の翻訳向けモデル。すでに読んで受け入れた Gemma 規約（`embeddinggemma:300m` と同じ）で、Google は訳文に権利を主張しない。発信元名・説明文を文脈として与えられる。Ollama の公式タグは未確認。
- Opus-MT（Marian、CC-BY-4.0）: 速いが言語対ごとのモデルで、ja→th などが欠ける。補助扱い。

どれも、最初に50件程度の実見出し（日・英・仏・独・中）で、訳の正確さ（固有名詞・数字・否定・法令名が変わらないか）と処理時間を比べてから決める。数字・日付・固有名詞が原文と一致しない訳は捨てて原文を出す、という機械的な検査を公開の処理に入れる。

## 推奨の形
1. 設定に「見出しを表示言語に翻訳する（機械翻訳）」を追加（既定はオフ）。オンのとき、記事の言語と表示言語が違う見出しだけ訳を出し、小さく「機械翻訳」と付ける。詳細画面は訳の下に原文の見出し。
2. 公開の処理で、A の利用条件の情報源の新着だけを訳し、`data/titles-<言語>.json`（記事 ID → 訳）に書く。生成日時を入れ、`list.json` と同じ世代のときだけ使う（世代を混ぜない規則を守る）。
3. B1・`titleOnly` の情報源は原文のまま（「この情報源は原文のみ」と分かる表示）。許諾を得たものから訳す。
4. 原文の言語が表示言語と同じなら何もしない（日本語の省庁の見出しを日本語表示で訳さない）。

## 決めてほしいこと
1. **方式**: A（公開の処理で事前に翻訳、言語ごとのファイル）でよいか。
2. **B1・titleOnly の見出し**: 訳さない（推奨・許諾後に訳す）か、「見出しだけなら訳しても見出しだけ」とみなして訳すか。
3. **エンジン**: MADLAD-400 と TranslateGemma 4B を実見出しで比べて選ぶ作業を進めてよいか（モデルの取得は数GB。公開の処理の時間が1回あたり数分〜十数分増える見込み）。
4. **既定**: オフ（推奨。原文が一次情報の基本）でよいか。
