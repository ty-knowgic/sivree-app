# Sivree 開発・試用の運営

開始: 2026-10-25。目的は PHILOSOPHY.md / PRODUCT.md に従い、根拠に近づける実務用ツールを育てること。BACKLOG.md は保留事項、本書は実行中の優先順位を管理する。

## 実行サイクル

1. 作業開始時に git status を確認。他の編集セッションと同時に変更しない。既存差分は消さない。
2. `npm run operations -- --refresh-snapshot` で公開データの写しと全チェックの証拠を取得。オフラインでは `npm run operations`。古い写しを現在の取得状況とみなさない。
3. 下表の最上位の未完了課題を一件選び、再現・利用者への影響・完了条件を先に記録する。
4. ローカルで修正し、該当テストを実行。共通処理を変えた場合は全チェックも実行。
5. UI変更は docs/local-testing.md に沿って実画面・実操作を確認。未実施は未確認と記す。
6. 結果と見逃しを本書へ反映し、次の一件を更新。テストの期待値を緩めて完了にしない。

証拠は `data/operations/<run>/report.json` と各ログ、最新参照は `data/operations/latest.json`。分類・地域の取りこぼしの候補は同じ実行の `coverage.json` と report.md の Coverage audit 節（[取りこぼしの監査](coverage-audit.md)。報告のみで終了コードに影響しない）。ソースの前後指紋が違う場合は一貫した診断ではない。

診断は一回15分、各チェック3分。終了コードは 0=自動チェック完了かつ収集品質にP0/P1なし、1=チェック失敗、2=未完了または収集品質に要対応。0も公開承認・UX合格・需要検証を意味しない。P2警告はレポートで確認する。

同じ原因で2回修正しても検証失敗、仕様変更・費用・外部送信が必要、または15分を超えた場合は、証拠と次の手段を残してその実行を停止する。公開・送信・料金やデータ収集方針の変更は別途判断。診断コマンドは自動修正・公開をしない。

定期実行はまだ未設定。この手順がチャット終了後も自走しているとは扱わない。まず診断と修正を分離して運用する。

## 2026-10-31 ブリーフィングの地域（利用者の指摘）

日本・米国・カナダを選んだ利用者の上位5件が、日本3・カナダ1・米国0になっていた（記事の多い地域に偏る）。地域の絞り込みで選べる地域は、ブリーフィングでも取れるようにした。

- 取り方（`buildBriefing`、`src/api.ts`）: 利用者が選んだ地域（選んでいなければ5地域）から1周に1件ずつ取る。従来の条件（同じトピック2件まで、配信サービス1件まで、同じ発信元1件まで、一致の強さ0.75以上）は保つ。新しい発表だけで5件そろえばその期間（24時間→48→72→120→168時間）、そろわなければ期間を広げる。新しい発表のない静かな地域は、1週間以内の発表から1件取り、件数の多い地域の最下位と入れ替える。候補のない地域は飛ばし、選んでいない地域は取らない。画面の順は関連度順。
- 同じ公開データでの前後（旧→新）: 日本・米国・カナダ×全トピック: 米国3・日本2 → 米国2・日本2・カナダ1。5地域×全トピック: 米国3・グローバル1・日本1 → 各地域1件。日本のみ・米国と欧州（欧州に強い一致がない）は変わらず。
- 試して直した: 地域を順に取る方式の最初の版は、先の地域が同じトピックの枠を使い切ると、後ろの地域が毎回弾かれて1件も入らなかった（`scripts/test-briefing.ts` が検出）。地域ごとの候補を、1件取るたびに選び直す形にした。また、地域ごとに「いちばん狭い期間」を選ぶ版は、新着の弱い配信記事が、少し古い強い記事に勝ったため外し、従来どおり「全体で5件そろう期間」に戻した。
- 処理時間: 5,000件で約50ms、20,000件で約160ms（ランキングを含む）。
- 追加の注意: 静かな地域のために期間が広がると、見出しは「最近のブリーフィング／過去N日間」になる。`scripts/audit.mjs` の「24時間でそろわない」の警告は、この場合も出る。
