# 公開前のローカル検証

## 起動

Node.js 22以上を使用します。初回のみ `npm ci` を実行します。

```bash
npm run preview
```

`http://127.0.0.1:4173` を開きます。初回は公開済みの静的JSONを取得します。以降は保存済みの写しで起動できます。元の情報源の巡回、要約の再生成、Ollamaの起動、GitHubへの変更、サイトの公開は行いません。

既定で `0.0.0.0` に待ち受け、LANアドレスとTailscaleアドレスも表示します。Mac内だけに限定する場合は `npm run preview -- --host 127.0.0.1` とします。

変更した `public/`・`src/`・静的ビルドスクリプトを監視します。`[ready]` が表示されたらブラウザを再読み込みします。自動リロードは設定の下書きを破棄するため行いません。

通常モードはService Workerを登録せず、記事のIndexedDBキャッシュも読み書きしません。プロフィールと選択状態は通常どおりブラウザ内に残ります。ビルド失敗時は直前の完成済み画面を維持し、失敗をターミナルに表示します。

ポートが使用中なら `npm run preview -- --port 4175` とします。URLが変わるとブラウザの設定領域も別になります。

## 記事データと情報源定義

```bash
npm run preview:data
```

公開されたmeta・記事・情報源・要約・分析のJSONを `data/preview/snapshot/` に保存します。取得前後の世代を照合し、更新が途中で起きたら取り直します。失敗・不正なデータの場合は以前の写しを維持します。記事の写しを更新すると、実行中の通常プレビューもビルドし直します。

情報源・専門パック・分野の定義は、毎回ローカルの `listSources()` から作ります。公開前の定義変更も検証できます。新しい情報源の記事が公開データにまだ存在しない場合、その情報源の記事件数は0になります。

プレビューのデータ更新時刻はローカルでデータ一式を生成した時刻です。元の公開データの日時は起動ログと `http://127.0.0.1:4173/__preview/status` の `snapshotGeneratedAt` で確認できます。記事自体の発表日時は変更しません。

ビルド結果は `data/preview/builds/` に分離します。完成してから配信先を切り替え、直前の版も保持して版付きファイルの混在を防ぎます。通常の `site/`、収集用の保存データ、`.env` は変更しません。これらのプレビューデータは既存の `.gitignore` の `data/` 対象です。

## 専門パックの操作確認

日本・米国などを選んで初回設定を終え、設定の「情報源」を開きます。

| 確認対象 | 合格条件 |
|---|---|
| 階層 | 専門パック → パック名 → 分野 → スイッチ付き情報源が一貫した位置に並ぶ |
| 政策・立法 | 展開した一覧の情報源名・スイッチで直接オン／オフできる |
| 分野の一括操作 | すべてオン／オフで、その分野の対象だけが変わる。展開位置は維持する |
| 共通情報源 | 金融庁などが複数箇所に出る場合、すべての選択状態と件数が連動する |
| 件数 | 分野・パック・全体の件数が即時に変わり、パック内の同じ情報源を重複して数えない |
| 検索 | 名称・分野名で絞り込み、該当分野が開く。解除後も選択は残る |
| 保存 | 保存して再度開いても選択が残る。保存せず戻った変更は破棄される |
| 対象外の地域 | 分野に対象がなければ理由と地域変更の操作があり、反応しないスイッチを並べない |
| 表示 | 日本語・英語、390px程度のモバイル幅とデスクトップ幅で、はみ出し・余白・重なりを目視する |

ボタンが存在することだけでは合格にしません。実際に情報源名をタップし、一部選択・全選択・全解除・保存・再表示まで確認します。

## 本番相当のキャッシュ・低速通信確認

```bash
npm run preview:production
```

`http://127.0.0.1:4174` で一度記事一覧を表示し、画面用ファイルの保存が完了するまで待ちます。本番相当モードは変更の自動ビルドを行いません。コード変更後は停止して再起動します。ソースと元データが同じなら同じ版を使うので、サーバーを再起動しても温まったキャッシュで検証できます。

その後 `Ctrl+C` で停止し、次で起動し直します。

```bash
npm run preview:production -- --delay-ms 7000
```

同じ `http://127.0.0.1:4174` に再訪します。キャッシュのある再訪で、通信の完了を待たず記事が読めるかを確認します。最初からキャッシュがない場合も確認するには、別ポートまたは別のテスト用ブラウザプロフィールを使用します。本番の設定をリセットする必要はありません。

15分以上離れて復帰する場合と、ページを閉じて開き直す場合は別々に確認します。閲覧中の一覧が勝手に差し替わらず、更新は明示操作で反映されることも確認します。開発者ツールでは `#listView` の `data-ready-ms` がページ開始から一覧描画完了までの時間、`data-shell` がキャッシュ制御状態を示します。ブラウザの通信中アイコンが消える時刻とは区別します。

## iPhoneで確認する

通常の `npm run preview` でLAN・Tailscaleからも接続できます。`npm run preview:lan` は同じ待ち受け設定を明示する別名です。

Macと同じWi-Fiに接続したiPhoneで、ターミナルに表示された `http://192.168.…:4173` 等を開きます。Mac上のプロセスが実行中で、接続をファイアウォールが許可している必要があります。

LANのHTTP接続は画面・タップ操作の確認用です。TailscaleのIPアドレスのHTTP接続も同様です。Service Workerを含むiPhoneの性能確認には、次のTailscale HTTPSを使います。

**Google同期のテストもTailscale HTTPSを使います。** Google OAuthはLANのHTTP/IPアドレスを生成元として許可しません（localhostは例外）。HTTPのプレビューでは認証ボタンの代わりに案内を表示します。設定のコピー／貼り付けによる移行はHTTPでも利用できます。

Google同期の初回のみ、[Google Cloud Console](https://console.cloud.google.com/auth/clients)で `public/sync.js` のCLIENT_IDに対応する既存のウェブOAuthクライアントを開き、「承認済みのJavaScript生成元」に起動時に表示されるHTTPSの生成元を追加してください。形式は `https://<MacのTailscale DNS名>:8443`（通常版）と `https://<同じDNS名>:8444`（本番相当版）です。パスや末尾の `/` は付けず、ポート番号を含めます。既存の本番用生成元は残してください。リダイレクトURI欄ではありません。

HTTPSでも未登録の生成元では `400: origin_mismatch` になります。Google Cloudの設定が反映されてから再試行してください。HTTPSの起動だけでGoogle登録が自動で行われるわけではありません。CLIENT_IDを変えるとDriveのアプリ専用データへのアクセスが変わるため、今回の問題のためにクライアントを新規作成しないでください。

```bash
# 画面確認: バックエンド4173、Tailscale HTTPS 8443
npm run preview:tailscale
# 本番相当: バックエンド4174、Tailscale HTTPS 8444
npm run preview:tailscale:production
```

Tailscaleが稼働していれば、端末のDNS名を自動検出してHTTPS用URLを表示します。初回にServe/HTTPSが未有効の場合は、管理画面の有効化URLを表示します。管理者がログインして有効化した後にコマンドを再起動します。別のサービスが同じHTTPSポートを使用している場合は上書きせず、`-- --https-port 8445` 等で別のポートを指定します。

iPhoneも同じtailnetに接続してTailscaleをオンにします。Tailscale接続では同じWi-Fiに限定されず、5GなどからもMacの検証環境へ接続できます。Macの電源・プレビュープロセス・Tailscale接続は維持する必要があります。Funnelによるインターネットへの一般公開は行いません。

Serveはバックグラウンド設定として残ります。不要になったときは、このプレビューに割り当てたポートだけを `tailscale serve --https=8443 off` / `tailscale serve --https=8444 off` で解除します。他のサービスを含む `tailscale serve reset` は使用しません。

通常モードと本番相当モードはポートを分けて使ってください。`127.0.0.1` と `localhost` も別の設定領域になるため、同じURLで比較します。Drive同期は自動テストで模擬検証できます。ローカルの操作確認のために本番のDriveへ接続する必要はありません。

## 自動チェック

```bash
npm test
# 同じチェック
npm run check:all
```

型、翻訳、情報源名、ブランド、XSS、同期、初期設定、一覧更新、グループ化、専門パック選択、保存・移行、プレビューサーバー、静的ビルドを順番に実行します。失敗した時点で停止します。公開処理は含みません。

個別に確認する場合は `npm run test:sources-ux`、`npm run test:performance`、`npm run test:shell`、`npm run test:preview` を使います。実機の目視・タップ確認は自動テストと別に行います。

ローカルで合格した変更をレビューし、公開が承認されてからGitHubへ反映します。本番は初めて動作を試す場所として使いません。
